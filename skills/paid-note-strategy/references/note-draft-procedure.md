# note.com下書き投入 手順書

完成済みの記事本文（Markdown）と、生成済みの画像一式を、note.comのブラウザ編集画面に流し込んで下書き保存するまでの手順。Claude Code側で実機検証して見つかった事故パターンを反映している。テーマ決めや執筆が終わったあと、このドキュメントだけを見て再現できるように書いてある。

**Codexでこの手順を使う場合の方針**：使えるClaude Codeセッションがあるなら、note.comへの実投入作業そのものをClaude Codeへ依頼するのがよい（この手順の実機検証はClaude Code環境で行われており、ブラウザ操作の勘所を直接持っている）。Claude Codeが使えない・失敗する場合は、Codex自身のブラウザ操作手段でこの手順をそのまま実行し、その旨を完了報告に含める。

ここに書く操作は特定のツール名に依存しない一般的な言い方（「クリックする」「スクリーンショットで確認する」「ファイルをアップロードする」）で統一している。「Claude Code実装メモ」は参考情報として残してあるが、Codex自身が実行する場合は自分の使えるブラウザ操作手段に読み替える。

## 0. 前提

- 対象記事の完成した`.md`ファイル（タイトル行＋`##`＝章見出し／`###`＝小見出し）
- 画像生成フロー（[references/title-formulas.md](title-formulas.md)と対をなす画像仕様、またはClaude Code側の`note-article-image-generator`）で作成済みの画像一式。ファイル名は`01_サムネイル.png`のように連番＋内容が分かる名前になっていること
- note.comに複数アカウントでログインしている環境であること

## 1. アカウントを確認する

作業を始める前に、note.comの編集画面右上や左上のプロフィールメニューを開き、**現在ログイン中のアカウント名**を確認する。ユーザーから指定されたアカウントと一致するかをその場で報告し、一致しない場合はユーザーに確認を取ってから進める。ログイン切り替え自体は自動化せず、必要ならユーザー自身に切り替えてもらう。

複数アカウントを使い分けている運用では、ここを飛ばすと別アカウントに投稿してしまう事故につながる。必ず作業の最初に行う。

## 2. 本文を下ごしらえする

Markdownのまま貼り付けると、`#`や`**`がそのまま文字として入ってしまう。次の2つを用意してから貼り付け作業に入る。

1. **プレーンテキスト本文** — Markdown記法を取り除いた、貼り付け用の本文
2. **見出しリスト** — どの行がH2（章）でH3（小見出し）かを記録したリスト。あとで一つずつ装飾するときに使う

これは`scripts/prep_note_body.py`で自動化できる。

```bash
python scripts/prep_note_body.py <記事.mdのパス> --out-dir <作業用ディレクトリ>
```

出力される`note_body_clean.txt`（貼り付け用本文）と`note_headings_list.txt`（見出しリスト、`H2`または`H3`とテキストがタブ区切り）を、この後の手順で使う。

**Claude Code実装メモ**：作業用ディレクトリにはスクラッチパッド（セッションの一時作業フォルダ）を使うとよい。

## 3. タイトルと本文を貼り付ける

1. クリップボード経由で本文を貼り付ける。OSのクリップボードにテキストを直接セットしてから貼り付ける方法が確実（キーボード入力のシミュレーションで長文を打たせると、途中で文字や数字が抜け落ちることがある）。
2. タイトル欄と本文欄、それぞれ正しいフィールドをクリックしてから貼り付ける。**同じ座標を使い回さない** — タイトルを入力した直後はタイトル欄の見た目のサイズが変わっていることがあり、貼り付け前と同じ座標でクリックしたつもりが、大きくなったタイトル欄の中に入ってしまい、本文全体がタイトルとして貼り付けられてしまう事故が起きる。フィールドを切り替えるたびに、直前のスクリーンショットで実際の位置を確認してからクリックする。
3. クリップボードは直前の操作（特に選択→削除のような操作）で不意に空になることがある。貼り付け直前にクリップボードの文字数を確認し、0文字なら即座に本文を再コピーしてから、間に他の操作を挟まずに貼り付け直す。

**Claude Code実装メモ**：PowerShellの`Get-Content -Raw -Encoding UTF8 <path> | Set-Clipboard`でファイル内容をクリップボードにセットし、対象フィールドをクリックしてから`ctrl+v`。貼り付け前に`Get-Clipboard -Raw`で文字数を確認する。

## 4. 貼り付け内容を検証する（最重要）

note.comのエディタには、空の段落にあらかじめ例文のようなプレースホルダー的なテキストが仕込まれていることがある。これは見た目だけのものではなく、実際にその場所に存在するテキストなので、大きな貼り付けがその近くに着地すると、**貼り付けた本文の先頭または末尾に、このプレースホルダーの断片が黙って混ざり込む**ことがある。

貼り付けが終わったら、エディタ全体のテキストを取得し、ソースの`.md`と**一字一句**突き合わせる。特に文書の**先頭**と**末尾**は事故が起きやすい箇所なので、そこだけでも必ず目視・文字列比較する。ズレがあれば、該当箇所をクリックして正確に何文字が混入・欠落しているかを特定し、選択して削除・訂正してから再度全文を検証する。

**Claude Code実装メモ**：ページ全体のテキストを取得できる手段（例：ブラウザのテキスト抽出ツール）でソースファイルと比較する。修正時は該当箇所へ`Home`→`Shift+→`を必要な文字数分押して正確に選択してから削除する。

## 5. 見出しを一つずつ装飾する

手順2で作った見出しリストの項目を、上から順に一つずつ処理する。まとめて処理しようとせず、1見出しごとに「適用→確認」のサイクルを回すこと。

各見出しについて：

1. 見出しのテキストを検索し、画面内にスクロールする
2. その行のテキスト全体を選択する（トリプルクリックなど、行全体を選ぶ操作）
3. 選択すると出てくるフローティングツールバーの「見出し」ドロップダウンを開く
4. **ドロップダウンの中身（大見出し／小見出し／指定なしの3項目）が実際に画面に表示されているのを確認してから**、目的の項目（H2なら大見出し、H3なら小見出し）をクリックする
5. 適用後、必ずスクリーンショットで確認する：
   - 目的の見出しが正しく装飾されたか
   - **直後の段落が意図せず一緒に太字・拡大されていないか**（選択範囲がずれて隣の段落まで巻き込むことが頻繁に起きる）
6. 隣接段落が巻き込まれていたら、その段落を選択して「指定なし」に戻し、本来の見出しが無事かを再確認する

この作業でよく起きる失敗と対処：

- **メニューがまだ描画し切っていないうちにクリックしてしまう**：ツールバーやドロップダウンは開いた直後、数百ミリ秒〜1秒ほど描画に時間がかかることがある。見た目上メニューが出ているように見えても、実際には別のボタン（太字・取り消し線・リストなど）が誤ってクリックされてしまうことがある。クリックの直後に必ずスクリーンショットを取り、期待通りの結果になっているかを確認してから次へ進む。
- **スクリーンショット取得自体が一瞬前の古い状態を返すことがある**：クリック直後の1枚目のスクリーンショットで変化が見えなくても、もう一度撮り直すと反映されていることがある。「変化なし」と判断する前にもう一度確認する。
- **誤操作（太字・取り消し線などが誤って適用された）に気づいたら**：直前の操作を取り消す機能（Undo）で戻してから、あらためて見出しドロップダウンを正確に開き直す。

**Claude Code実装メモ**：見出しドロップダウンを開いた直後は`見出し`ボタンへの参照が毎回新しくなるため、要素の参照IDを使い回さず、座標クリック＋都度スクリーンショット確認の組み合わせが安定する。

## 6. 画像を挿入する

先に「どの画像を、どの見出し・話題の区切りの前後に置くか」を全部決めてから作業に入る（本文を読み返し、見出しの直前や、ひとつの話題が終わった自然な区切りを選ぶ。文章やセンテンスの途中には絶対に入れない）。1枚ずつ、以下のサイクルを回す。

1. 挿入したい位置の**直前の段落**をクリックする。その段落が複数行に折り返されている場合は、**表示上の最後の行**をクリックすること（最初の行をクリックして「行末へ移動」の操作をしても、その操作は見た目上の行の末尾にしか移動せず、段落の本当の末尾には届かない）。
2. カーソルを段落の本当の末尾へ移動する操作をしたら、**ズームして実際にカーソルが最後の文字の直後にあるかを確認する**。ここを飛ばすと、次の改行操作が段落の途中に入ってしまい、文章が真っ二つに割れて画像がその間に挟まる、という壊れ方をする。
3. 段落末尾で改行し、空の段落を作る
4. その空段落に出てくる「＋」のような挿入ボタンをクリックし、挿入メニューが**完全に表示されるまで待ってから**（描画途中でクリックすると閉じるだけで何も起きなかったり、別の項目が選ばれたりする）、「画像」を選ぶ
5. 出てきたファイル選択の仕組みに、ローカルの画像ファイルを直接渡す（OSのネイティブなファイル選択ダイアログをクリックで開こうとしても、ブラウザ操作の仕組みからは中身が見えず操作できないので、ファイルを直接渡せる手段を使う）
6. 挿入できたら、前後の文章が欠落・重複・分断していないかスクロールして目視確認する

**もし段落が途中で割れてしまったら**（症状：本来ひと続きだった文が、画像の前後で「〜によ」「って作られている」のように不自然に分断されている）：
1. 分断された後半部分の段落を選択して削除する
2. 前半部分の段落の末尾に、削除したテキストをそのまま入力し直して文をつなげる
3. ソースの`.md`と突き合わせて、その周辺の文章が完全に一致することを確認する
4. 正しい位置を選び直して画像挿入をやり直す

**Claude Code実装メモ**：ファイル選択の仕組みは、ページ内のファイル入力要素を検索して見つけ、ローカルのファイルパスを直接渡せるアップロード用ツールを使う。サムネイル画像だけは本文とは別の、記事最上部にある専用のアップロード枠（クリックすると「画像をアップロード」のメニューが出る）から設定する。

## 7. 最終検証と保存

1. 見出し装飾・画像挿入がすべて終わったら、**文書全体のテキストをもう一度取得し、ソースの`.md`と最初から最後まで一致するか確認する**。部分的な確認では手順5・6で起きた事故を見逃す。
2. 一致を確認したら「下書き保存」を実行する
3. 保存ボタンの表示が「保存中」から通常の状態に戻るのを確認し、保存が完了したことを確かめる
4. 完了報告には、確認したアカウント名、文字数、装飾した見出し数、挿入した画像枚数と配置、最終検証の結果を含める

## つまずいたときの心構え

- ブラウザ操作の接続が一時的に切れることがある。焦らず同じ操作をもう一度試せば大抵は復帰する。
- 「クリックしたのに反映されていない」ときは、まずスクリーンショットを撮り直す。それでも反映されていなければ、同じ場所をもう一度クリックする。
- 何か想定外のことが起きたら、その場で本文全体を読み返して壊れていないかを確認する癖をつける。小さな事故は早期発見なら簡単に直せるが、気づかず保存すると後で見つけにくい。
